----- как выглядит простейший кОнфиг вебпака:

он пишется в стиле CJS, 


-- то есть он должен экспортировать Ноде ОБЪЕКТ  с конфигурацией:

(дефолтный экспорт)

module.exports = {
  entry: './dist/script.js',  // говорим, где у нас в проекте точка входа - файл, где происходит рендер приложения и т.п.
}

entry - точка входа

output - чуть сложнее, тут нужно указать в какую директорию собирать проект-результат
и для output нужно не относительный путь, а абсолютный 

для генерации абсолютного путиу Ноды есть инструмент 'path' , его устанавливать уже не надо, он поставляется вместе с Нодой сразу



---- 
const path = require('path')

module.exports = {
  entry: './dist/script.js',  // говорим, где у нас в проекте точка входа - файл, где происходит рендер приложения и т.п.
  output: {
    path: path.resolve(__dirname, 'dist')
  }
}

-----

__dirname - в эту константу будет записанан текущая директория

- --------------------   ФИшка вебпака - что он позволяет ВСТРАИВАТЬ  внутрь своего алгоритма СБОРКИ различные трансформации (причем не только для JS, а чего угодно)

module: {
    rules: [{
      test: /\.js$/,
      use: 'babel-loader'
    }]
  }

- описываем правило:
- каждый раз когда Вебпак встречает файл удовл регулярке (то есть js файл), 
он будет выполнять специальную функцию перед тем как этот файл попадет в итоговый бандл 

Спец.функция (или серия спец.ф-й) - называется "ЛОАДЕРЫ"
Лоадеры - одна из основных концепций вебпака 
лоадеры позволяют трансформировать код перед тем как они будут попадать в итоговый бандл 

в нашем случае мы используем бейбел-лоадер

но вебпак про него ничего не знает
он так же построен на системе т.наз. плагинов, - нам нужно его явно установить 

"npm install babel-loader"

- babel-loader делает то же что и обычный babel, когда мы запускали его руками, просто делает это в констексте вебпака 

и когда вебпак анализирует конфиг и видит такую запись, он понимает что нужно искать пакет с таким именем в  node_modules

-------------- ПОЧЕМУ так произошло?

- дело в том что мы импортируем не только наш JS , но также импортируем JS из Node модулей - Реакт и Реакт ДОМ,

а там файлов великое множество 

и теперь вебпак, каждый раз натыкаясь на js любой , в том числе на JS Реакт и Реакт ДОМ, - прогоняет его через "babel-loader"

- а это довольно ресурсоемкий - дорогостоящий процесс, как любая трансформация кода.



---- НАМ на самом деле,

- НИ реакт, НИ реакт-дом прогонять через бейбел лоадер НЕ НАДО, т.к. там все конструкции уже стандартные , там нет JSX

поэтому нам нужно сказать вебпаку, что "babel-loader" актуален только для тех файлов, которые создаем мы.

А из node_modules НЕ нужно ничего тащить через "babel-loader", -

из node_modules просто тащить файлы в том же виде в каком они лежат

чтобы это сказать вебпаку, добавляем в конфиге "exclude":


module: {
    rules: [{
      test: /\.js$/,
      use: 'babel-loader',
      exclude: /node_modules/
    }]
  }
